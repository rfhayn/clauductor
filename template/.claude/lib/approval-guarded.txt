# approval-guarded.txt: the paths a delegated approval may never cover (OPS-127).
#
# With APPROVAL_DELEGATED="1" in .claude/project.conf, Claude may record a change's approval for
# the owner (`change-approval.sh <id> --delegate <owner>`), except for a change that names one of
# these paths in a task line of its tasks.md, or whose branch's diff touches one: those loosen a
# control on Claude, so the owner approves them. One path or directory per line (a trailing `/`
# is optional), matched on whole path segments anywhere in a path, so `.claude/hooks` covers
# `template/.claude/hooks/x.sh`.
#
# This file is the framework's list: `clauductor update` keeps it current, so add nothing here.
# Your own paths go in .claude/local/approval-guarded.txt, the same format. The key and both lists
# are read from origin/<MAIN_BRANCH>, never from the branch under test, so a branch cannot loosen
# them for itself (a repository with no remote reads the disk). An empty list refuses every
# delegation. The list follows AGENTS.md's "What executes each rule": what runs a control is here,
# and checks/approval-guarded.sh fails a path the table names in bold that neither list guards.
