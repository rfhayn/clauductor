## What happened

`pr-merge-guard.sh` gains rule 15: while `.claude/model-roles.json` says `attribution.enabled` is not true, a squash merge is refused unless it names its body, and refused if any line of that body is a `Co-authored-by:` trailer (any case, indented or not). A squash with no body gets GitHub's default, the branch commits' messages with their trailers, which is how #289, #290 and #291 came to carry one. `merge_argv` now also reports the merge method (`W squash|merge|rebase`) from the same parse, so a merge commit or a rebase is not judged. The rule is one function, `coauthor_why`, so it moves whole to `.claude/merge.sh` (ADR-0012, OPS-162). merge-pr step 4 already merges with `--body-file`; it now says the body holds no such line while attribution is off. Every refusal has a row in `checks/merge-guard.sh` that failed against the hook without the rule (10 rows red), then passed.

## Decisions

- **A literal `--body` is accepted beside `--body-file`.** The row says "without `--body-file`"; what it guards against is GitHub's default body, which any named body replaces. `cg_body` reads both the same way and the trailer test is the same, so requiring a file would add nothing. An unreadable body (a substitution, stdin, a relative file after a `cd`) is refused.
- **A trailer is a line that starts with the key.** `Co-authored-by` in prose or a code span is a mention, not a trailer, and git and GitHub never credit it; this rule's own squash body names the key. Leading blanks and a blank before the colon still count, failing closed on how loosely GitHub parses.
- **The switch is `attribution.enabled`, the one build-change reads.** Off unless it is true while the file exists; a file that does not parse keeps the rule on. No file at all (a project without the model) leaves it off, as rule 12 does.
- **A `gh api` merge is held as a squash.** Its method sits in a field the guard does not read, so it needs a clean `commit_message`. merge-pr never merges that way.
- **AGENTS.md is unchanged** (the lead's scope): no rule number its What-executes rows cite moved.

## Surprises

This repo's own `.claude/` copy of the check failed where the template's passed: the rule 13 fixture copies the project's `model-roles.json`, and this repo turns attribution off, so rule 15 refused those squashes first. The fixture now sets attribution on, as it already set provenance off for rule 12.
