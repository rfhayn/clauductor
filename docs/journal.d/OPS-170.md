## What happened

Every full gate printed "this repo's framework differs from the template (project.conf differs in APPROVAL_DELEGATED GATE_DOCS); both sets run every check". `framework_matches_template` compares every project.conf key but CONF_NOT_READ, and this repo set both keys to "1" on purpose (OPS-127, OPS-89), so the 15 CHECKS_ONCE checks ran in both sets on every gate. Both keys now join CONF_NOT_READ. Before: this repo's set ran the 15 in 317 s (one at a time, `sh .claude/checks/run.sh <name>`, load average 6 at the start and 97 at the end, other gates running; inside the lane's sandbox, where gate, machine-quiet and people fail on `ps`, so their 50, 61 and 37 s are of a partial run). After: `check_sets` on main's `steps.sh` says "differs ... APPROVAL_DELEGATED GATE_DOCS"; on this branch's it says "matches; this repo's set leaves to the template's:" all 15, so this repo's set spends 0 s on them, and the template's set still runs each once.

## Decisions

- Add the keys to CONF_NOT_READ rather than move a check out of CHECKS_ONCE: no CHECKS_ONCE check reads either key. Their only readers are `change-approval.sh` (APPROVAL_DELEGATED) and `run-local.sh` (GATE_DOCS). No CHECKS_ONCE check runs `change-approval.sh`, and `gate` runs `run-local.sh` only in its fixture, whose project.conf it writes; conf.sh sets both keys' defaults before it reads a project.conf, so not even an inherited variable reaches it.
- `check-sets.sh`'s key scan read only the check file, so it missed a key read by a file the check sources or runs from ROOT in place, with ROOT's project.conf: `review-lane` runs `review-lane.sh` there, `premise-check` sources `modules/premise-check/lib/receipt.sh`, and every check sources `lib.sh` and `conf.sh`. The scan now reads those too, and fails a check that names ROOT's project.conf, which would carry every key into a fixture. A fixture case shows it finding a key read through each path, and not one read by a copy in a fixture.
- The brief's scope named `template/scripts/ci/steps.sh`, `template/.claude/checks/check-sets.sh` and `plugin/`. CONF_NOT_READ and check-sets are this repo's own (the template ships one check set and no CHECKS_ONCE), so the template and the plugin do not change.

## Surprises
