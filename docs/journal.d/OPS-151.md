## What happened

The row first shipped as #304: `lane-sync.sh`, one script that a lane would run outside the sandbox for update, rebase, merge and reset, approved per run. It was gated green, but review round 1 found HIGH, and the owner closed it unmerged. This PR is the reshaped row.

Probed from the session's sandbox on 2026-10-28:
- a lane's worktree can write its `.claude/hooks` and `.claude/skills`, but not `.claude/agents` or `template/.claude/agents`;
- the main checkout can write none of those;
- `.git/config` and `.git/hooks` are denied everywhere.

Both playbooks' *Lanes* sections now hold that table and say who does each step. The lane syncs its hooks and skills inside the sandbox. The main session creates the worktree and applies a reviewed agents diff, outside the sandbox. A lane opened as a session of its own has its opener do both (ST-15's row says so). No command runs a lane's own files outside the sandbox. This lane's own `.claude/hooks` and `.claude/skills` copies were synced inside the sandbox: by `cp`, then confirmed by a sandboxed `framework/clauductor update --dry-run` built from this checkout.

## Decisions

- **No unsandboxed lane-sync script** (the owner, 2026-10-28). #304 is closed, with its remote branch deleted. Its commits are kept on the local branch `ops/ops-151-lane-sync-closed-304`. Round 1 found HIGH: an approved run would execute lane-editable files, namely `conf.sh` and `project.conf`, the lane's `framework/` build, and git under the lane-writable repo config and hooks. The approver's `git diff origin/main` check could also be bypassed with `update-ref`. In-session lanes can write their worktree's hooks and skills inside the sandbox, so the script was not needed.
- **OPS-90's probe (4) is answered, for an interactive session.** A reviewer launched by a background lane hands its report back to the MAIN session. Its hand-back to the lane fails ("the agent that spawned you is no longer running"), and it has no SendMessage. This is the reverse of `claude -p` on 2026-10-18. It is recorded in `no-silent-wait.sh`'s header, in a merge-pr step 3 note and in the owner-queue item. Nothing in the template relays the report (round 1's finding 4), so neither says to wait for one. ST-16's row owns the relay. AGENTS.md's row says nothing now false, so it is unchanged.
- **Probe (2) is moved to #305.** It needs an interactive session's own PreToolUse on `AskUserQuestion`, with the refusal reaching that session's Claude. A subagent lane has no AskUserQuestion of its own to fire, and it cannot observe a hook firing in the orchestrator. Probe (1), agent teams, is dropped (the owner).

## Surprises

- The owner's `~/.zshrc` sets `CLAUDUCTOR_FRAMEWORK` to the main checkout. That variable outranks the binary's own checkout in the template search. So a lane's `framework/clauductor update` reads the MAIN checkout's template, and reports nothing to do, unless the lane sets it to its own checkout. This repo's playbook now says so.
- `git worktree add` from the sandbox created the branch but not the worktree, because `.git/config` is denied.
