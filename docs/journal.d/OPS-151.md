## What happened

`template/.claude/lane-sync.sh` (with its `.claude/` and plugin copies) runs `clauductor update`, `git rebase`, `git merge` or `git reset --hard` against `origin/<main>` in a lane's linked worktree, and nothing else. It is the one command a lane asks to run outside the sandbox, whose write deny on `.claude/hooks` and `.claude/skills` stays. It refuses the main checkout (git dir equals the common dir), a directory outside git, another repository's worktree, a worktree `git worktree list` does not name, and any other subcommand or argument. `checks/lane-sync.sh` holds it. With the main-checkout guard deleted, 9 of its assertions fail, and the fixture's main checkout loses an unpushed commit. Both playbooks' *Lanes* sections say so. The script is on `approval-guarded.txt`, since it runs unsandboxed. This repo's own copy was brought along by the script itself: `lane-sync.sh update`, run outside the sandbox from this lane.

## Decisions

- **`merge` is a fourth operation beyond the row's three.** A lane with an open PR merges `origin/main` rather than rebasing, and that merge writes the same directories.
- **In this repo `update` builds `framework/clauductor` from the lane's checkout and pins `CLAUDUCTOR_FRAMEWORK` to it.** Any other project runs the `clauductor` on PATH. There is no no-binary equivalent of `update` to fall back on.
- **`update` passes only `--dry-run`, `--create-missing` and `--prune`.** An approved run stays the run the approver read, so `--template-dir` and `--force` are refused. Its review answers come on stdin, as for `clauductor update`.
- **The plugin's copy serves no one repository.** It syncs the current directory's, and still refuses a main checkout.
- **OPS-90's probe (4) is answered, for an interactive session.** A reviewer agent launched by a background lane subagent hands its report back to the MAIN session, not to the lane. Its hand-back to the lane fails ("the agent that spawned you is no longer running"), and it has no SendMessage. This is today's evidence (2026-10-28), the reverse of `claude -p` on 2026-10-18. It is recorded in `no-silent-wait.sh`'s header, in `merge-pr` step 3 (such a lane waits for the main session to relay the report) and in the owner-queue item. AGENTS.md's row says nothing now false, so it is unchanged.
- **Probe (2) remains unprobed.** It needs an interactive session's own PreToolUse on `AskUserQuestion`, and the refusal has to reach that session's Claude. This lane is a subagent: it has no AskUserQuestion of its own to fire, and a hook firing in the orchestrator cannot be observed from here. It needs a terminal session to run it. Probe (1), agent teams, is dropped (the owner, 2026-10-28).

## Surprises

- The owner's shell sets `CLAUDUCTOR_FRAMEWORK` to the main checkout. The template search reads it before the binary's own checkout, so the first `lane-sync.sh update` read the MAIN checkout's template and reported nothing to do. The fix pins it in the script.
- `git worktree add` from the sandbox created the branch but not the worktree: `.git/config` is write-denied. It needed an unsandboxed run, the same class of failure this row is about.
